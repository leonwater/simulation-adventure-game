# 모험가 키우기 — 개발 작업 기획

기획서(`모험가 키우기 기획서`, 2026-10-17)와 UI 시안(11개 화면)을 바탕으로 한 Unity 모바일 앱 개발 계획입니다.

## 1. 목표

- Unity(uGUI) 기반 **모바일 앱**(Android/iOS, 세로 화면). 웹 빌드 아님.
- 1차 범위: 던전 30층, 직업 4종, 화면 11종 + 대장간·수련장·설정.
- 모든 수치는 임시값이며 `GameBalance.cs` 한 곳에 모아 밸런싱에서 조정합니다.

## 2. 구조

| 계층 | 위치 | 내용 |
| --- | --- | --- |
| Core | `Assets/Scripts/Core` | 순수 C# 게임 로직. UnityEngine 참조 없음(`noEngineReferences`). 단위 테스트 대상 |
| Game | `Assets/Scripts/Game` | Unity 런타임. 부트스트랩, 코드로 생성하는 uGUI 화면, 저장 파일 입출력 |
| Editor | `Assets/Scripts/Editor` | 프로젝트 자동 설정(메인 씬 생성, 빌드 씬 등록, 세로 화면·앱 이름 등) |
| Tests | `Assets/Tests/EditMode` | NUnit 테스트. Unity Test Runner와 `dotnet test` 양쪽에서 실행 |
| Verify | `tools/verify` | Unity 없이 검증: Core 테스트 + Unity 참조 DLL 대상 전체 컴파일 검사 |

화면은 프리팹 없이 코드로 만들어 씬·프리팹 병합 충돌이 없고, 어떤 환경에서든 저장소만 받으면 바로 열 수 있습니다.

## 4. 기획서에서 비어 있어 임시로 정한 것

기획서에 수치나 규칙이 없는 부분은 아래처럼 정했습니다. 모두 `GameBalance.cs`에서 바꿀 수 있습니다.

| 항목 | 임시 규칙 |
| --- | --- |
| 필요 경험치 | 100 × 레벨^1.5 (이전 기획서 값) |
| 사망 시 경험치 −20% | 현재 레벨 필요 경험치의 20%를 잃되 0 아래로 내려가지 않음 |
| 시작 능력치 | 전 능력치 5, 직업 주력 3종 +3 |
| 피해 공식 | 공격력 × 배율 × 100 / (100 + 방어력) × (1 − 강인함 감소율) |
| 공격 성공률 | 50% + (주 공격 능력치 − 적 요구치) × 5% + 정밀 보정, 5~95% |
| 적 피격 확률 | 90% − 회피(민첩 × 0.5%) |
| 스킬 강화 | 최대 +5, 단계당 위력 +10% |
| 강화석 | +6~+8은 1개, +9~+10은 2개 필요. 던전 드롭 |
| 퀘스트 종류 | 토벌(특정 몬스터 처치), 채집(재료 수집), 정복(층 보스 처치) |
| 휴식 방 | 최대 HP 40% 회복 + 디버프 해제 |
| 자동 저장 | 방 하나를 끝낼 때마다, 마을 행동마다, 앱이 백그라운드로 갈 때 저장 (플레이 테스트 후 조정) |
| 30층 보스 처치 | 엔딩 화면 표시 후 계속 플레이 가능 |

### 파트별 오류 확인에서 고친 것

- 파트 1: 필요 경험치 기대값 오기 (10^1.5 = 3,162) — 테스트 수정
- 파트 3: 가방 8개 구매 비용(127,500G)보다 적은 골드로 검사 — 테스트 수정
- 파트 4: "통로으로" 조사 오류 — "통로로"
- 파트 5: 공격력 0인 적도 최소 피해 1을 주는 점을 놓친 테스트 — 적을 기절시켜 검증
- 파트 5: 전투 기록 조사 "(를)" 표기 — 받침에 따라 자동 선택하는 `Names.Josa` 추가
- 파트 7: Core `Text`·`EventSystem`이 Unity 클래스와 이름 충돌 — `Names`·`EventRules`로 변경
- 파트 7: 사망 정산 문구에서 잘못된 조사 호출로 생길 수 있던 예외 — 수정
- 파트 7: 버튼 눌림 색이 테두리에만 적용되던 문제 — 안쪽 채움에 적용

### 아직 확인하지 못한 것

- 이 개발 환경에는 Unity 에디터가 없어, 실제 화면 배치와 터치 동작은 Unity에서 처음 열 때 확인이 필요합니다.

  - 종족마다 1개, 고블린 왕·리치·드래곤은 2~3개 조합. 수치는 층이 깊을수록 커짐 (예: 방어막 1층 1회 → 25층 4회)
  - 행동 예고(강타 준비·회복 주문 영창·부하 소환 예고·탈진)를 보스 이름 자리에 주황색 '!'로, 처음 보면 안내 1회
  - 수치 보정: 특성만큼 HP·공격력 조정, `tools/balance/run.sh boss`로 켬/끔 1:1 비교 (대부분 ±5%)
  - 승인되지 않은 '돌 피부'(가고일)는 방어막으로 대신, '특성 태그·설명'은 넣지 않음
- 밸런싱 (보통 기준): 1~7층 적 HP +25·공격력 +3.5 (1층 100% → 8층 0%), 어려움·하드코어 40%, 쉬움·튜토리얼 없음
  - 봇 시뮬레이션: 3층 돌파 3.5 → 5.8회, 10층 24 → 33회 / 어려움 30층 정복 3/8명 (깨질 수 있음 확인)
- 튜토리얼: 첫 튜토리얼(마을 소개·상점) 동안 건너뛰기 없음, 버튼은 '건너뛰기'로 작게, 말풍선 강조(금색·초록·빨강),
  1층 보스를 잡아도 아래층 불가 → 귀환, 캐릭터 정보·순간이동 위치·귀환 잠금·보스 예고 안내 추가
- 퀘스트: 같은 대상(몬스터·재료·보스 층)은 하나만, 난이도 단계로 등급·목표 층·요구량·보상을 함께 결정, 카드에 보상(골드·경험치)
- 던전: 순간이동 버튼 미니맵 오른쪽 아래(28×32), 하단 가방·캐릭터 정보·귀환(폭 48, 미발견 시 붉은 회색),
  방 결과 카드를 먼저 크게(보물 목록 한 줄씩), 방 안 행동 보라색, 레벨 업 창은 캐릭터 화면과 같은 고정 폭 −/값/+
- 캐릭터 정보 창(던전 하단 가운데·전투 머리줄·내 원): 능력치, 상태 이상(1턴 피해·남은 턴), 탐험 효과, 진행 중 퀘스트, 상태 이상 안내
- 아이템: 종류별 색 원 7종, 장비 이름은 등급 색, 칸 안에 착용 레벨·지금 장비 대비 수치, 가방·창고 4열
- 던전 밖 모든 화면 머리줄 오른쪽에 골드 + 설정 버튼, 상점 갱신 버튼 폭 절반, 난이도 설명·프롤로그 교체
- UI 정렬 점검 (화면 전체 코드 검토):
  - 원인: `UI.TextButton`이 안의 글자 칸 때문에 줄을 채우려 늘어남 → 기본으로 늘어나지 않게, 같은 폭은 `width: 0, flexW: N`으로
  - 머리줄 제목 가운데 맞춤, 확인 팝업·레벨 업·캐릭터·가방·상점·등록·이어하기 버튼 줄 같은 폭, 설정 선택 버튼·스킬/수련 버튼·탭·하단 메뉴 같은 폭
  - 던전 하단 버튼 실제 폭 48, HP 칸 110 고정, 길 선택 버튼 높이 60 통일, 전투·이벤트 머리줄을 던전 머리줄과 같게(높이 60, HP 막대)
  - 레벨 업 줄은 캐릭터 화면과 같은 아이콘 24·글자 12·높이 56, 상점 수량은 고정 폭 −/값/+ + 10개씩
  - 시설 화면 여백 16·일러스트 높이 260 통일, 판매 카드 이름 줄임, 적이 3마리 이상이면 상태 태그 2개, 탐험 효과 태그 한 줄 2개
